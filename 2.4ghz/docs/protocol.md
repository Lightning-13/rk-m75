# RK M75 2.4 GHz RGB Protocol

Experimental reverse-engineering notes for the RK M75 2.4 GHz receiver.

## Receiver

- VID: `0x258A`
- PID: `0x0148`
- Manufacturer: SINO WEALTH
- Product: Gaming KB
- Interface: USB HID interface 1
- Relevant HID collection: `FF02/0002`
- Relevant HID report ID: `0x13`

The receiver exposes multiple HID collections. The RGB protocol was
identified by capturing traffic generated by the official RK software
while the keyboard was connected through 2.4 GHz.

## USB Transport

The official software sends RGB commands to the receiver using HID
`SET_REPORT` control transfers.

The relevant report has:

- Report ID: `0x13`
- Report type: Output
- Report size: 20 bytes
- Interface: 1

## Common Packet Structure

Observed packets use the following general structure:

    13 88 CC SS LL ... payload ... CS

Where:

- `13` = HID report ID
- `88` = observed protocol marker
- `CC` = command
- `SS` = sequence/chunk field
- `LL` = observed length/type field
- `CS` = 8-bit additive checksum

Observed checksum rule:

    checksum = sum(bytes[0:19]) & 0xFF

The checksum has been verified against captured packets.

## Command 0x01 — Per-Key RGB

Command `0x01` is used by the official software for per-key RGB
updates.

Observed structure:

    13 88 01 00 15 RR GG BB 01 II 00 00 00 00 00 00 00 00 00 CS

Where:

- `RR GG BB` = RGB color
- `II` = LED index
- `CS` = additive checksum

### Confirmed LED indices

The following physical keys were captured individually and compared
against the validated wired RK M75 LED mapping:

| Key | RGB | Wireless LED index | Wired LED index |
|---|---|---:|---:|
| ESC | Red | 0 | 0 |
| A | Red | 9 | 9 |
| W | Green | 14 | 14 |
| M | Blue | 46 | 46 |
| SPACE | Green | 35 | 35 |
| ENTER | Blue | 81 | 81 |

All tested indices match.

This strongly indicates that the 2.4 GHz protocol uses the same logical
LED index space as the wired implementation.

## Command 0x07 — Multi-Report RGB Update

The official software also sends command `0x07` as a sequence of seven
20-byte reports.

Observed sequence numbers:

    00
    01
    02
    03
    04
    05
    06

The first report contains the RGB color bytes:

    13 88 07 00 1E RR GG BB ...

The remaining reports contain structured payload data.

The complete meaning of the payload has not yet been determined.

Captured RGB changes confirm that the RGB values in the command change
with the selected color.

## Refresh Behavior

The official software repeatedly sends the RGB state rather than
sending it only once.

The observed command `0x07` sequence repeats periodically.

Exact timing and the purpose of this refresh behavior are still under
investigation.

## Current Confidence

### Confirmed

- Receiver VID/PID
- HID interface used by the official RGB control traffic
- HID report ID `0x13`
- 20-byte output reports
- HID `SET_REPORT` transport
- Command `0x01`
- Per-key RGB field layout
- Shared LED index space with wired mode
- Additive 8-bit checksum
- Seven-report structure for command `0x07`

### Not yet decoded

- Complete meaning of command `0x07`
- Meaning of all fields in its seven reports
- Exact wireless keepalive requirements
- Whether all RGB operations use the same command set
- Whether the receiver requires additional initialization/state packets
- Whether the wireless protocol can safely be driven independently of
  the official software
