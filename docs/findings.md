# Reverse Engineering Findings

This document records findings from reverse engineering the Royal Kludge
RK M75 RGB lighting protocol and the official RK Keyboard Software.

The primary hardware tested throughout this project is:

Vendor ID:  0x258A
Product ID: 0x0163
Device:     RK-M75RGB New layout

---

## 1. USB Device

The RK M75 exposes a vendor-specific HID interface used for RGB control.

Observed device information:

Vendor ID:   0x258A
Product ID:  0x0163
Interface:   1
MI:          MI_01
Usage Page:  0xFF02

The RGB interface is exposed through the vendor HID collection associated
with `MI_01`.

---

## 2. HID Feature Report

RGB communication uses a HID Feature Report.

Observed properties:

Report ID:   0x09
Report Size: 520 bytes

A captured RGB Feature Report was successfully replayed directly to the
keyboard.

The replay caused the keyboard to immediately display the captured RGB
state, confirming that the report contains the RGB framebuffer data.

---

## 3. RGB Packet

The RGB lighting packet uses packet type:

0x08

A separate status packet type was also identified:

0x0B

The lighting report uses a fixed-size 520-byte Feature Report.

Controlled captures were used to identify the RGB framebuffer.

No checksum was observed in the lighting packet.

No sequence counter was observed in the lighting packet.

---

## 4. RGB Framebuffer

The RGB framebuffer contains RGB values corresponding to individual
keyboard lighting positions.

The framebuffer can be generated directly from Python.

This was demonstrated by constructing an all-red frame without using the
official RK software and sending it to the keyboard.

The keyboard immediately displayed the generated RGB state.

Individual key colors can also be generated by modifying the corresponding
framebuffer position.

---

## 5. Vendor Device Configuration

The official RK Keyboard Software uses a shared configuration system for
multiple Royal Kludge keyboard models.

The main configuration file contains a large list of supported VID/PID
combinations.

The RK M75 is explicitly identified as:

VID:    0x258A
PID:    0x0163
Device: RK-M75RGB New layout

This confirms that the official software recognizes PID `0x0163` as the
RK M75 RGB new-layout device.

---

## 6. Device-Specific Keyboard Configuration

The device-specific keyboard configuration was found under the `Dev`
directory of the official RK Keyboard Software installation.

Typical Windows path:

C:\Program Files (x86)\RK Keyboard Software\Dev\<PID>\

For the RK M75:

C:\Program Files (x86)\RK Keyboard Software\Dev\0163\

The exact installation path may differ depending on the software version
or Windows installation. The important structure is:

RK Keyboard Software
└── Dev
    └── 0163

The PID-specific configuration contains the keyboard layout used by the
official software.

Relevant configuration values include:

RGBKb=1
LayoutKeyNum=84
KbLayout=5
LayerNum=3

The configuration contains:

[KEY]
[FN1]

sections describing the keyboard layout and Fn-layer behavior.

---

## 7. Key Mapping Discovery

The complete 81-key RGB mapping was not obtained by manually capturing
each key.

Instead, the mapping was derived from the vendor's PID `0x0163`
keyboard-layout configuration.

Each `[KEY]` entry contains an internal key index associated with the RGB
framebuffer position.

Two mappings had already been independently established through hardware
testing:

A      → LED 9
SPACE  → LED 35

The vendor configuration contained the same indices.

This provided an independent cross-check between the vendor configuration
and the reverse-engineered RGB framebuffer.

---

## 8. 81-Key Validation

After deriving the complete mapping, all 81 mapped keys were illuminated
using a generated RGB Feature Report.

Result:

81 / 81 mapped keys illuminated

A second row-based color test was performed to verify that the indices
corresponded to the expected physical positions.

Different keyboard rows were assigned different colors.

The physical keyboard matched the expected layout.

This validates the complete 81-key RGB mapping currently used by the
library.

---

## 9. Additional Layout Positions

The vendor configuration reports:

LayoutKeyNum=84

while the current RGB keymap covers the 81 main keyboard keys.

The remaining three logical positions have not been mapped.

The RK M75 contains a rotary encoder / volume knob, so these additional
positions may correspond to encoder-related controls.

This has not been experimentally established and is intentionally outside
the current 81-key RGB mapping.

---

## 10. Firmware Lighting Takeover

A single externally generated RGB Feature Report does not remain active
indefinitely.

With the official RK software closed:

Send RGB report
      ↓
Requested RGB state appears
      ↓
Approximately 1 second
      ↓
Keyboard firmware reclaims lighting state

This behavior occurs independently of the official software.

---

## 11. Lighting-Off Experiment

The official RK software was used to set the keyboard lighting mode to
Off.

The software was then closed.

A single generated RGB Feature Report was sent.

Observed result:

RGB state appears
      ↓
Approximately 1 second
      ↓
Keyboard returns to black

Therefore, setting the official software's lighting mode to Off does not
provide a persistent external RGB mode.

---

## 12. Continuous Feature Report Experiment

A keepalive test repeatedly transmitted the same RGB Feature Report.

Test configuration:

Update rate: 10 Hz
Interval:    100 ms
Duration:    More than 60 seconds

The keyboard remained at the requested RGB state for the entire test.

This demonstrates that continuous Feature Report transmission can maintain
external RGB control without the official RK software running.

---

## 13. Firmware Takeover After Streaming Stops

After the 10 Hz keepalive test was stopped, the keyboard reclaimed the
lighting state.

Observed delay:

Approximately 1 second

The resulting behavior can be summarized as:

Single report
    ↓
Temporary RGB control
    ↓
~1 second
    ↓
Firmware takeover


10 Hz repeated reports
    ↓
Continuous RGB control


Stop repeated reports
    ↓
~1 second
    ↓
Firmware takeover

---

## 14. Current Streaming Knowledge

Real-time RGB control is therefore proven to be possible.

The current known-good configuration is:

520-byte RGB Feature Report
+
10 Hz continuous transmission

The following values have not yet been characterized:

* Minimum stable update rate
* Maximum stable update rate
* Maximum long-term update rate
* Actual visible frame rate
* Latency
* Behavior at higher transmission rates
* Behavior during long-duration streaming

These will be investigated separately from the key-mapping work.

---

## 15. Other RK Keyboard PIDs

The official RK configuration contains many other RK keyboard PIDs.

This indicates that the vendor software is designed to support multiple RK
keyboard models through a shared configuration/driver architecture.

However, the presence of a PID in the vendor configuration is **not proof
of compatibility with this project**.

Only the following device has been experimentally validated:

VID:    0x258A
PID:    0x0163
Device: RK-M75RGB New layout

Other PIDs should be treated as unverified.

Researchers interested in another RK keyboard should independently verify:

* HID interface
* Feature Report size
* Report ID
* Packet format
* Framebuffer layout
* Key mapping
* Firmware behavior
